# Избранное, плейлисты, очередь и история

Эти данные относятся к аккаунту. Передавайте bearer-токен и используйте
ID записей из каталога. В примерах `12` и `34` обозначают записи,
которые вы уже нашли. [Первые запросы к API](./overview.md)

## Избранное

Вызовите `PUT /api/v1/me/recordings/12/reaction`:

```json
{"reaction":"like"}
```

Трек появится в `GET /api/v1/me/favorites`. Чтобы поставить дизлайк,
передайте `{"reaction":"dislike"}`. Чтобы снять оценку, вызовите
`DELETE /api/v1/me/recordings/12/reaction`. Оба действия уберут трек из
избранного. Сервер собирает избранное из лайков.

## Создайте плейлист и задайте порядок треков

1. Вызовите `POST /api/v1/me/playlists`:

   ```json
   {"name":"Вечер","description":""}
   ```

2. Возьмите `id` и `version` из ответа. Вызовите
   `PUT /api/v1/me/playlists/{id}/tracks` с этой версией:

   ```json
   {"version":1,"recording_ids":[12,34,12]}
   ```

Массив заменяет **весь** порядок. Чтобы добавить один трек к существующему
плейлисту, сначала прочитайте позиции через
`GET /api/v1/me/playlists/{id}/tracks`, затем добавьте ID в свой список
и отправьте его целиком. Повторяющиеся ID допустимы, а пустой массив
очищает плейлист.

> [!TIP]
> При чтении нескольких страниц проверьте, что у всех одна `version`.
> При `409` перечитайте плейлист и согласуйте изменения. После успешной
> записи возьмите новую версию из ответа.

### Поделитесь плейлистом

Вызовите `PUT /api/v1/me/playlists/{id}/visibility` с текущей версией:

```json
{"version":2,"is_public":true}
```

После этого другие вошедшие пользователи увидят его в
`GET /api/v1/playlists`. Редактировать плейлист может его владелец.
Чтобы снова сделать его личным, отправьте `is_public: false`.

## Сохраните очередь и позицию

Прочитайте `GET /api/v1/me/queue`. Чтобы заменить порядок и сохранить
выбранный трек, отправьте `PUT /api/v1/me/queue`:

```json
{"version":0,"recording_ids":[12,34,12],"current_position":3,"position_ms":0}
```

Подставьте версию из GET. Ноль подходит для начальной пустой очереди.
В примере `current_position: 3` выбирает **второе** вхождение записи 12:
позиции считаются с единицы. Если трек не выбран, передайте
`current_position: null` и `position_ms: 0`.

Порядок можно сохранить один раз, а выбор и смещение менять через
`PUT /api/v1/me/queue/playback`. Передайте туда текущую `version`,
`current_position` и `position_ms`. Ограничение на размер списка
берите из `collection_limit` в capabilities.

Клиент сам запускает плеер, переключает треки и управляет повтором.
Историю нужно записывать отдельно.

## Запишите прослушивание

После окончания или пропуска трека отправьте `POST /api/v1/me/history`:

```json
{
  "event_id":"device1-play-0001",
  "recording_id":12,
  "started_at":1780000000,
  "listened_ms":95000,
  "duration_ms":180000
}
```

Подставьте время начала в Unix-секундах и реальное время прослушивания
в миллисекундах, без пауз и перемотки. Ограничьте его известной
длительностью. Если длительность неизвестна, передайте `null` или
опустите `duration_ms`.

| Ответ | Что он значит |
| --- | --- |
| `201` | Новое событие сохранено. |
| `200` | Тот же отчёт уже был сохранён. |
| `409` | Такой `event_id` уже использовали для других данных. |

Создавайте новый `event_id` для каждого проигрывания. При сетевом сбое
храните отчёт локально и отправляйте его повторно с тем же ID и телом.

Сервер возвращает `full`, если прослушано хотя бы полтрека или четыре
минуты, в зависимости от того, что короче. При неизвестной длительности
порог составляет четыре минуты. Более короткие события получают `short`.
Для экрана истории используйте `GET /api/v1/me/history`.
