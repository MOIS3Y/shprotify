# Рекомендации и загрузки

Добавьте рекомендации, когда уже работают [воспроизведение](./playback.md)
и [личные коллекции](./collections.md). Лента помогает найти музыку.
Плеер сможет её открыть, если в библиотеке есть подходящий аудиофайл.

## Создайте ленту и получите результаты

Отправьте один из запросов ниже в `POST /api/v1/me/discovery/feeds`.
Личная лента работает с локальной библиотекой. Ленте по тегу нужен
включённый Last.fm. [Источники и настройка](../guide/discovery.md)

::: code-group
```json [Личная лента]
{"kind":"personal"}
```
```json [Тег Last.fm]
{"kind":"tag","tag":"jazz"}
```
:::

1. После `202 Accepted` запросите статус по адресу из `Location`.
   В теле ответа `id` означает задание, а `feed_id` означает ленту.
2. Когда задание завершится со статусом `completed`, прочитайте
   `GET /api/v1/me/discovery/feeds/{id}/items`, подставив ID ленты.
3. Для следующего обновления вызовите
   `POST /api/v1/me/discovery/feeds/{id}/refresh`. Следите за статусом
   нового задания. При сбое можно оставить прежние результаты на экране.

## Покажите, почему появилась рекомендация {#display-recommendations}

| Поле | Как использовать |
| --- | --- |
| `candidate.provider` и `candidate.url` | Покажите источник. Если URL есть, предложите открыть страницу источника. |
| `reasons` | Покажите пояснения сервера, например «Из общей библиотеки» или «Подходит под ваш интерес к исполнителю». Это текст для человека. Для действий используйте структурированные поля. |
| `id` | Используйте для действий с рекомендацией, например для «Хочу добавить». |
| `candidate.kind` и `local_id` | По типу выберите экран записи или релиза из локального каталога. При отсутствии совпадения `local_id` будет `null`. |
| `has_registered_audio` | Для записи показывает, что к ней привязан аудиофайл. Сервер проверяет файл на диске при запросе потока. |

Сохраняйте порядок, в котором сервер вернул элементы. `score` используется
при ранжировании и не подходит для показа в процентах или в виде рейтинга
трека. [Как подбираются рекомендации](../guide/discovery.md#how-recommendations-work)

Для записи с `local_id` и `has_registered_audio: true` откройте список
файлов и предложите воспроизведение. Для сопоставленного релиза можно
показать его треки. Если аудио пока нет, предложите сохранить находку.

## Сохраните находку или скройте её

Сначала прочитайте `GET /api/v1/me/discovery/candidates/{id}`. Для
изменения отправьте текущее состояние с вашими правками в
`PUT /api/v1/me/discovery/candidates/{id}/feedback`. Ниже пример отметки
«Хочу добавить» для кандидата, которого ещё не оценивали:

```json
{"version":0,"reaction":null,"hidden":false,"wanted":true}
```

Берите версию из `feedback.version`. `hidden: true` скрывает предложение,
а `wanted: true` сохраняет его в `GET /api/v1/me/discovery/wishlist`.
Реакция на рекомендацию хранится отдельно от лайка записи в библиотеке.
Для редактирования отметок читайте `feedback`. Верхнеуровневое поле
`reaction` показывает реакцию, которую сервер учитывает для выдачи.

Чтобы сделать обычный плейлист, отправьте
`POST /api/v1/me/discovery/feeds/{id}/playlist` с текущей версией ленты:

```json
{"version":1,"name":"Джазовые находки"}
```

В ответе `included` показывает, сколько записей добавлено, а
`skipped` показывает, сколько пропущено. В плейлист попадают подходящие
записи из каталога. При обновлении ленты плейлист остаётся прежним.

## Найдите аудио для трека

Перед показом загрузок проверьте `downloads_enabled` в capabilities и
`enabled` у провайдера из `GET /api/v1/downloads/providers`. Сервер
может разрешить загрузки, даже если внешний источник временно недоступен.

Отправьте один из запросов в `POST /api/v1/me/downloads/searches`:

::: code-group
```json [Из рекомендаций]
{"kind":"candidate","id":42}
```
```json [Запись каталога]
{"kind":"recording","id":12}
```
```json [По названию]
{"kind":"query","title":"Название трека","artists":["Исполнитель"]}
```
:::

Подставьте реальные ID или название. Для кандидата должен быть выбран
отдельный трек. После `completed` у задания поиска получите результаты
через `GET /api/v1/me/downloads/{id}/sources` с ID задания.
Покажите название видео, канал и длительность, чтобы пользователь мог
сам выбрать нужную версию.

## Загрузите выбранный результат

Отправьте `POST /api/v1/me/downloads` с ID выбранного результата поиска:

```json
{"source_id":17}
```

Это ID результата недавнего успешного поиска данного аккаунта.
После принятия откройте `GET /api/v1/me/downloads/{id}` с ID **нового**
задания. Показывайте этапы скачивания, проверки и импорта. Общий размер
`total_bytes` может быть `null`.

После `completed` возьмите `recording_id` и `file_id` из ответа.
Теперь можно открыть файл через обычное [воспроизведение](./playback.md).
При ошибке покажите `message` задания. Отменить или повторить задание
можно через `POST /api/v1/me/downloads/{id}/cancel` или
`POST /api/v1/me/downloads/{id}/retry`, если текущее состояние это допускает.
