# Авторизация и ошибки

Храните отдельное подключение для каждого сервера и аккаунта. При входе
получите токен, а затем запросите `GET /api/v1/me`, чтобы узнать, кто
вошёл и какие права у пользователя.
[Пример входа с curl](./overview.md)

## Вход, хранение токена и выход

Отправьте имя и пароль в `POST /api/v1/auth/login`. Ответ содержит
`access_token`, `token_type: "Bearer"` и `expires_at` в Unix-секундах.
В следующих запросах передавайте токен в заголовке:

```http
Authorization: Bearer TOKEN
```

| Чем вошли | Срок действия | Как отозвать |
| --- | --- | --- |
| Парольная сессия | До `expires_at`, по умолчанию 30 дней. | `POST /api/v1/auth/logout` завершает текущую сессию. Сброс пароля завершает все парольные сессии аккаунта. |
| Персональный API-ключ | До явного отзыва. | Администратор отзывает ключи аккаунта. Сброс пароля на них не влияет. |

Токен сессии непрозрачен. Используйте `expires_at` из ответа и
предложите повторный вход, когда срок истечёт. Shprotify выдаёт
сессию заново при входе по паролю.

> [!IMPORTANT]
> Храните токен в системном хранилище учётных данных, если оно доступно.
> Исключайте его из журналов и используйте только для запросов к тому
> серверу, который его выдал.

## Что доступно до входа

`GET /api/v1/capabilities` доступен всем. По `public_catalog` можно
решить, открывать ли каталог до входа. Для личных действий и выдачи
ссылки на аудио нужен токен, а для управления сервером нужна роль
`admin`. Чужой приватный ресурс обычно вернёт `404`.
[Настройки доступа для администратора](../guide/accounts.md)

## Как показывать ошибки

В ответах Shprotify смотрите HTTP-статус и `error.code`.
`error.message` можно показать как пояснение. У запроса `HEAD` тела
ответа нет. Если ответ пришёл от прокси или соединение оборвалось,
обработайте ситуацию и без JSON.

| Статус | Что сделать в клиенте |
| --- | --- |
| `400`, `413`, `415` | Проверьте параметры, размер или тип тела запроса. |
| `401` | Если токен недействителен, предложите снова войти. |
| `403` | Объясните, какие права нужны для действия. |
| `404` | Покажите, что ресурс недоступен. |
| `409` | Для устаревшей версии перечитайте данные. Для фонового задания проверьте причину конфликта. |
| `422` | Покажите, какие значения нужно поправить. |
| `429` | Подождите перед повтором. Учитывайте `Retry-After`, если он есть. |
| `5xx` | Покажите сбой сервера и дайте вернуться к действию позже. |

Успешный запрос статуса задания тоже может сообщить об ошибке.
Проверяйте итоговое состояние задания. Если сетевой ответ на запись
потерялся, сначала проверьте, успела ли она сохраниться.
