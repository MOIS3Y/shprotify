# Каталог и воспроизведение

Чтобы включить трек, найдите запись в каталоге, выберите её аудиофайл
и передайте поток плееру. Для всех примеров понадобится токен.
[Получить токен и проверить поток](./overview.md)

## Найдите музыку в каталоге

| Что открыть | Запрос |
| --- | --- |
| Исполнители | `GET /api/v1/artists` |
| Альбомы исполнителя | `GET /api/v1/artists/{id}/releases` |
| Треки альбома | `GET /api/v1/releases/{id}/tracks` |
| Записи | `GET /api/v1/recordings` |
| Аудиофайлы записи | `GET /api/v1/recordings/{id}/files` |
| Поиск по каталогу | `GET /api/v1/search?q=...&limit=20` |

Поиск возвращает `kind`, `id` и `title` для каждого результата.
По `kind` выберите экран исполнителя, альбома или записи.

Для следующей страницы используйте `limit` и `offset`. В списке записей
есть `has_more` и `total`. Поиск и список файлов возвращают
`items`, `limit` и `offset`. Если страница короче запрошенного
размера, список закончился. Точную форму ответа смотрите в
[справочнике API](../reference/api.md).

## Различайте запись, позицию и файл

| Что это | Где используется |
| --- | --- |
| Запись (`recording_id`) | Само исполнение. К нему привязаны избранное, очередь и история. |
| Позиция в альбоме | Вхождение записи на определённом диске и месте в альбоме. |
| Аудиофайл (`file_id`) | Один файл записи в конкретном формате. Для потока нужны ID записи и файла. |

У записи может быть несколько файлов или пока ни одного. Покажите
отсутствие аудио, если список файлов пуст, и выбирайте формат, который
поддерживает декодер клиента. Сервер отдаёт аудио в исходном формате.

Чтобы подгрузить данные видимых строк одним запросом, используйте
`GET /api/v1/recordings/batch?ids=12,34,56`. Для реакций подойдёт
`POST /api/v1/me/recordings/reactions` с телом
`{"recording_ids":[12,34,56]}`. Число ID ограничено `batch_limit`
из capabilities. ID и версии передаются как 64-битные целые.
В JavaScript учитывайте предел точности обычного `Number`.

## Нативный плеер

Для записи 12 и файла 7 передайте движку URL
`/api/v1/recordings/12/files/7/stream` на адресе сервера и
заголовок `Authorization: Bearer TOKEN`. Движок должен добавлять
заголовок и к запросам перемотки.

| Запрос | Что вернёт сервер |
| --- | --- |
| `HEAD` | Заголовки без аудио. |
| `GET` с одним допустимым диапазоном `Range` | `206 Partial Content` и `Content-Range`. |
| Диапазон за пределами файла | `416 Range Not Satisfiable`. |
| Запрос нескольких диапазонов | Полный файл с `200 OK`. |

## Браузерный плеер {#browser-playback}

Для элемента `<audio>` запросите временную ссылку через
`POST /api/v1/recordings/{id}/files/{file_id}/playback-ticket`
с заголовком `Authorization`. В ответе будут `stream_url` и
`expires_at` в Unix-секундах. Соберите полный URL относительно адреса
сервера и присвойте его `audio.src`.

Ссылка относится к одному файлу. Когда она истечёт, запросите свежую
перед следующим сетевым запросом к аудио. Если меняете `src` при
воспроизведении, сохраните позицию и восстановите её после загрузки
метаданных. Выход или отзыв исходных учётных данных также отключает ссылку.

> [!IMPORTANT]
> В URL для плеера используйте выданный `stream_url`. Токен аккаунта
> передавайте только в заголовке `Authorization`.

Если страница плеера открывается с другого домена, попросите администратора
добавить её адрес в [настройки CORS](../guide/proxy.md#если-веб-плеер-на-другом-домене).

## Обложки и офлайн

- **Обложка.** Запросите `GET /api/v1/artwork/{kind}/{id}`. Для закрытого
  каталога приложите токен. Сохраните `ETag` и отправляйте его в
  `If-None-Match`. Ответ `304` означает, что можно оставить свою копию.
- **Офлайн.** Кэшируйте исходное аудио и метаданные локально. Для потока
  аудио сервер не выдаёт `ETag` или `Last-Modified`. Запрос с
  `If-Range` возвращает весь файл. Если вы не можете проверить, что файл
  остался прежним, начните скачивание заново.

Когда воспроизведение работает, добавьте [очередь и историю](./collections.md).
