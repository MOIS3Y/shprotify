# Документация и справочники

Сайт собирается из Markdown на VitePress. Для правок текста поднимите
локальный сайт. OpenAPI и DBML обновляйте из сервера и миграций, когда
меняется то, что они описывают.

## Откройте локальную документацию

Понадобятся Node.js 22 или новее, Python 3 и Graphviz (`dot`).
В `nix develop` они уже есть.

```sh
cd docs
npm ci --ignore-scripts
npm run dev
```

Откройте адрес, который напечатает VitePress. После установки зависимостей
проверки и сборка сайта работают с локальными файлами.

## Найдите нужный файл

| Что правите | Где искать внутри `docs/` |
| --- | --- |
| Установка и управление сервером | `guide/` и `ru/guide/` |
| Подключение и разработка клиентов | `clients/` и `ru/clients/` |
| Справочники и участие в проекте | `reference/` и `ru/reference/` |
| Меню и оформление | `.vitepress/config.ts` и `.vitepress/theme/` |
| Примеры Compose и TOML для Docker | `public/examples/`. Страницы включают эти файлы в примеры. |

У английской и русской страниц один и тот же путь под своим языковым
префиксом. Меняйте пример Compose в исходном файле, чтобы правка попала
в оба руководства.

## Проверьте работу сайта

```sh
npm run build
npm run preview
```

Сборка включает `npm run check`: проверку типов, переводы, OpenAPI и DBML.
VitePress проверяет внутренние ссылки. `preview` показывает собранный сайт
с тем же базовым путём. Чтобы собрать вариант для GitHub Pages, используйте
`DOCS_BASE=/shprotify/ npm run build`. По умолчанию сайт собирается для `/`.

::: details О зависимостях VitePress
Для VitePress 1.6.4 в `package.json` задано переопределение Vite до
6.4.6 с исправлениями безопасности. При обновлении VitePress проверьте,
можно ли убрать переопределение и правку локального поиска в
`.vitepress/config.ts`. После изменения пакетов запустите `npm audit`.
:::

## Обновите OpenAPI

После изменений маршрутов или схем соберите сервер из корня репозитория:

```sh
cargo build --locked
cd docs
npm run api:export
```

Экспортёр запускает временный сервер на loopback с отдельной базой,
читает его схему и сохраняет её в `docs/public/openapi.json`. Проверьте
изменения в этом файле и включите его в ту же правку. Для проверки без
перезаписи используйте `npm run api:export -- --check`.
Если бинарник находится в другом месте, передайте `--binary ПУТЬ`.

## Обновите DBML {#update-dbml}

После добавления SQL-миграции выполните в `docs/`:

```sh
npm run schema:export
npm run check
```

Скрипт применит миграции к чистой SQLite-базе и обновит
`docs/database.dbml`. Сохраните DBML вместе с миграцией. SVG-диаграммы
сайт создаёт при сборке. [Как читать схему базы](./database.md)
