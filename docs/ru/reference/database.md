# Схема базы данных

Схему SQLite задают SQL-миграции из `migrations/`. Чтобы получить DBML
и диаграммы, скрипт применяет эти миграции к пустой базе. Так схема
в документации проверяется по тому же SQL, который использует сервер.

## Найдите нужную область

| Область | Какие данные искать |
| --- | --- |
| Каталог | Исполнители, альбомы, записи, аудиофайлы, метаданные и обложки. |
| Личные данные | Аккаунты, авторизация, реакции, плейлисты, очереди и история. |
| Discovery | Ленты, рекомендации, отметки и связи с загрузками. |
| Фоновые процессы | Сканирование, работа с метаданными, загрузки и расписания. |

Выберите область. Нажмите на изображение, чтобы открыть SVG в полном
размере. Серые таблицы показывают связи с другими областями.

DBML содержит все колонки, ключи, индексы и ограничения показанных таблиц.
Условия частичных индексов записаны в примечаниях. SQLx и FTS5 создают
служебные таблицы, которые опущены в диаграммах.

## Связи за пределами внешних ключей

На диаграмме показаны объявленные в SQLite внешние ключи. Часть правил
хранится в триггерах или проверяется сервером:

- Запись в `catalog_metadata` может относиться к исполнителю, альбому
  или записи. Связь поддерживают триггеры каталога.
- Временная ссылка на аудио действительна, пока действуют исходные
  учётные данные. Сервер проверяет их при запросе.
- История правок и удалений сохраняет идентификаторы, чтобы можно было
  понять, к каким данным относилась операция.

## Измените схему

Добавьте в `migrations/` новый SQL-файл с возрастающим номером. SQLx
сверяет применённые миграции по контрольным суммам, поэтому сохраняйте
их содержимое. Покройте изменение тестом рядом с нужным модулем базы
и [обновите DBML](./documentation.md#update-dbml).

Триггеры, представления для клиентских запросов и полнотекстовый поиск
описаны в SQL. Если из диаграммы неясно, что произойдёт при записи,
смотрите миграцию.
