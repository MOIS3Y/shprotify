# Резервные копии и обновления

Копия папки `data/` сохраняет каталог, аккаунты, плейлисты, историю,
обложки и файлы, которые скачал Shprotify. Сохраните также настройки
запуска и исходную музыку. Так можно восстановить всю библиотеку,
включая личные данные пользователей.

## Сделайте резервную копию

Команды ниже рассчитаны на установку из [быстрого старта](./quick-start.md).
Выполняйте их из папки с `compose.yaml`.

| Что сохранить | Зачем |
| --- | --- |
| Вся папка `data/` | В ней база SQLite, обложки и загрузки. Если рядом с базой остались файлы `-wal` или `-shm`, они попадут в ту же копию. |
| `compose.yaml`, а также `.env` и `config/`, если они есть | Чтобы вернуть настройки, пути и выбранный образ. |
| `music/` или папка с исходной коллекцией | База хранит записи каталога, а сами аудиофайлы остаются в ваших папках. Их можно сохранить отдельно. |

Если меняли путь к базе или загрузкам, проверьте, что их папки входят в
копию. [Где лежат файлы](./configuration.md#где-лежат-фаилы)

Запишите текущую версию, чтобы знать, с каким образом восстанавливать
копию:

```sh
docker compose exec shprotify shprotify --version
```

Остановите Shprotify на время копирования. В строке с `tar` добавьте
`.env` и `config/`, если пользуетесь ими. Пример создаёт архив рядом
с папкой установки.

```sh
backup="../shprotify-$(date +%Y%m%d-%H%M%S).tar.gz"
docker compose stop shprotify && (
  umask 077
  sudo tar -czf - compose.yaml data > "$backup"
)
```

После копирования снова запустите сервер. Если `tar` завершился ошибкой,
сделайте новую копию. Готовый архив можно проверить командой ниже:

```sh
docker compose start shprotify
tar -tzf "$backup"
```

Храните архив в месте с ограниченным доступом. В нём есть личные данные
и могут быть ключи внешних сервисов.

> [!NOTE]
> Для копирования через `tar` остановите сервер и берите всю папку
> `data/`. У работающей SQLite часть записанных изменений может
> оставаться в файле `-wal`. [Как SQLite хранит WAL](https://sqlite.org/wal.html#the_wal_file)

## Восстановите сервер из копии

1. Остановите старый контейнер командой `docker compose stop shprotify`,
   если он ещё запущен. Сохраните его папку с данными отдельно.
2. Из родительской папки распакуйте архив в **новую пустую папку**.
   Замените имя файла на имя своей копии.

   ```sh
   mkdir shprotify-restore && cd shprotify-restore &&
     sudo tar --numeric-owner -xzpf ../shprotify-YYYYMMDD-HHMMSS.tar.gz
   ```

3. Верните исходные аудиофайлы. Пути **внутри контейнера** должны совпасть
   с прежними, например `/music/`. Убедитесь, что пользователь контейнера
   с UID 1000 может читать и писать в `data/` и читать аудиофайлы.
4. В `.env` укажите [версию образа, на которой сделана копия](./deployment.md).
   Запустите сервер из восстановленной папки командой `docker compose up -d`.

Проверьте вход, каталог и воспроизведение нескольких треков. В базе будут
данные на момент копирования. Повторное сканирование пополнит каталог,
а плейлисты, аккаунты и историю вернёт только копия базы.

## Обновите Shprotify

1. Прочитайте примечания к релизу и сделайте резервную копию.
2. Если используете фиксированный тег, смените его в `.env` на тег нового
   релиза. Если следите за `latest`, оставьте его.
3. Скачайте образ и запустите контейнер с ним.

   ```sh
   docker compose pull shprotify && docker compose up -d shprotify
   ```

Когда сервер запустится, проверьте, что он отвечает `{"status":"ok"}`.
Если используете Traefik, подставьте свой HTTPS-адрес.

```sh
curl -fsS http://localhost:3000/api/v1/health
```

После этого проверьте вход и воспроизведение.

> [!IMPORTANT]
> При запуске новая версия может изменить схему базы. Если нужно откатиться,
> запустите прежний образ с копией данных, сделанной до обновления.

Если сервер не запускается или не отвечает, откройте
[«Решение проблем»](./troubleshooting.md).
