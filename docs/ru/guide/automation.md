# Расписания и автоматизация

Shprotify может находить новые файлы в музыкальных папках, обновлять
личные ленты и предлагать уточнения к данным альбомов и треков.
Расписания выполняет сам сервер.

| Что запустить | Кто настраивает | Что получится |
| --- | --- | --- |
| Сканирование папок | Администратор в настройках сервера | Новые файлы появятся в общем каталоге. |
| Обновление ленты | Владелец ленты | В выбранной ленте появятся свежие рекомендации, если источник их нашёл. |
| Поиск метаданных | Администратор для выбранного исполнителя, альбома или трека | Появятся предложения, которые можно проверить и принять. |

## Включите расписания и сканирование

Администратор включает расписания общей настройкой `automation.enabled`.
В примере ниже сервер также сканирует папки с музыкой раз в час.

::: code-group
```yaml [Compose]
# В блоке environment сервиса shprotify
SHPROTIFY_AUTOMATION__ENABLED: "true"
SHPROTIFY_AUTOMATION__LIBRARY__SCAN_INTERVAL_SECONDS: "3600"
```
```toml [TOML]
[automation]
enabled = true

[automation.library]
scan_interval_seconds = 3600
```
:::

Сканируются подключённые папки библиотеки. Shprotify пропускает файлы,
которые не изменились. Если нужны только расписания лент или метаданных,
оставьте `scan_interval_seconds = 0`.
[Как применить настройки](./configuration.md)

## Обновляйте личную ленту

Сначала [создайте ленту](./discovery.md). Если ваш клиент поддерживает
расписания, откройте настройки нужной ленты и задайте интервал.
По умолчанию предлагается шесть часов. При стандартных настройках сервера
можно выбрать интервал от одного часа до 30 дней. Интервал задаётся
для каждой ленты отдельно.

::: details Как задать интервал вручную в Swagger
[Войдите под своим аккаунтом](./quick-start.md#воидите) и откройте
раздел **Discovery**.

1. Вызовите `GET /api/v1/me/discovery/feeds/{id}/schedule` с ID ленты.
   Запомните `version` и проверьте допустимые границы интервала в ответе.
2. Выполните `PUT /api/v1/me/discovery/feeds/{id}/schedule` с тем же ID.
   Подставьте полученную версию. В примере новая лента обновляется
   каждые шесть часов (`21600` секунд).

   ```json
   {"version":0,"enabled":true,"interval_seconds":21600}
   ```

3. В ответе проверьте `next_run_at`. Чтобы выключить расписание для этой
   ленты, отправьте тот же запрос с актуальной версией и `enabled: false`.
:::

## Настройте регулярный поиск метаданных

Сначала [включите поиск в MusicBrainz](./metadata.md), затем разрешите
для него расписания. Общий переключатель `automation.enabled`
должен быть включён.

::: code-group
```yaml [Compose]
# В блоке environment сервиса shprotify
SHPROTIFY_AUTOMATION__METADATA__ENABLED: "true"
```
```toml [TOML]
[automation.metadata]
enabled = true
```
:::

Когда настройки применены, выберите в клиенте с управлением метаданными
конкретного исполнителя, альбом или трек и включите расписание для него.
По умолчанию предлагается поиск раз в сутки. Это же нижняя граница
интервала, пока администратор её не изменит.

::: details Как включить расписание метаданных вручную в Swagger
[Войдите администратором](./quick-start.md#воидите). В разделе
**Admin: Automation** вызовите `GET /api/v1/metadata/{kind}/{id}/schedule`.
Укажите ID объекта и его тип: `artist`, `release` или `recording`.

Затем выполните `PUT /api/v1/metadata/{kind}/{id}/schedule` с теми же
параметрами. Подставьте `version` из ответа GET и интервал в секундах.

```json
{"version":0,"enabled":true,"interval_seconds":86400}
```
:::

> [!NOTE]
> Сервер ищет по подтверждённому MusicBrainz ID или по названию. Результаты
> ждут проверки администратора. Пока у объекта есть предложения на проверке,
> следующий автоматический поиск откладывается. [Как проверить предложения](./metadata.md)

## Когда запускаются задания

Первый запуск нового расписания происходит после заданного интервала.
После успешного задания начинается отсчёт следующего интервала.
Shprotify проверяет, что пора запустить, примерно каждые 30 секунд.
Если сервер был выключен, он не будет запускать отдельное задание за каждый
пропущенный интервал.

Если кажется, что расписание не сработало, посмотрите время следующего
запуска (`next_run_at`) и состояние последнего (`last_status`). В
`paused_reason` или `message` может быть пояснение, например отключённый
источник или предложение, которое ещё нужно проверить. После ошибки
сервер может подождать дольше обычного перед повторным запуском. Администратор
может посмотреть расписание сканирования в **Admin: Automation** через
`GET /api/v1/automation`.

Чтобы приостановить все расписания, задайте `automation.enabled = false`
и примените настройки сервера. Записанные интервалы сохранятся, а
сканирование, обновление лент и поиск метаданных по-прежнему можно
запускать вручную. [Все настройки расписаний](./configuration.md#полный-справочник)
