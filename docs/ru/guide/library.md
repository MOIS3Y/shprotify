# Добавление музыки

Положите файлы в папку с музыкой и попросите Shprotify обновить библиотеку.
При сканировании сервер читает теги, чтобы разложить треки
по исполнителям и альбомам. Исходные файлы остаются на месте.

## Добавьте файлы в библиотеку {#импорт-папки}

Если ваш клиент поддерживает сканирование библиотеки, запустите его
из приложения. Ниже показан ручной вариант через Swagger.

1. Скопируйте музыку в `./music/` рядом с `compose.yaml`. Если при установке
   подключили свою папку, скопируйте файлы туда.
2. Откройте Swagger по адресу `http://localhost:3000/docs` и
   [войдите администратором](./quick-start.md#воидите).
3. В разделе **Admin: Library** выполните `POST /api/v1/library/scans`.
   Скопируйте `id` из ответа.
4. В том же разделе откройте `GET /api/v1/library/scans/{id}`. Подставьте
   этот ID и проверяйте статус, пока он не станет `completed`.
5. В разделе **Recordings** выполните `GET /api/v1/recordings`. Записи
   появятся в списке `items`.

> [!TIP]
> Команда `shprotify scan` пригодится, если нужно посмотреть теги и
> свойства файлов. Она выводит отчёт в терминал и оставляет каталог
> без изменений.

### Если трек не появился

Проверьте ответ `GET /api/v1/library/scans/{id}`. Поле `roots` показывает,
какие папки просматривал сервер, а `imported` показывает количество новых
файлов. Если статус `failed`, причину остановки ищите в поле `message`.
Ошибки по отдельным файлам видны в `GET /api/v1/library/scans/{id}/errors`
с тем же ID. Список покажет, с какими файлами возникли проблемы.
Остальные файлы могли добавиться, даже если в отчёте есть ошибки.

- Если нужной папки нет в `roots`, проверьте, куда она подключена в Compose
  и какой путь указан в настройках Shprotify.
- Если файл есть в папке, проверьте, что контейнер может его прочитать.
  Сканер пропускает символические ссылки внутри папок библиотеки.
- Если сканирование ещё идёт, дождитесь его завершения. Сервер выполняет
  одно сканирование за раз.

## Подключите ещё одну папку {#подключение-еще-однои-папки}

Например, если часть музыки лежит в `/srv/archive`, добавьте эту строку
в существующий список `volumes` сервиса `shprotify`:

```yaml
- /srv/archive:/archive:ro
```

Docker покажет серверу эту папку по пути `/archive` в режиме чтения.
Укажите обе папки библиотеки в том месте, где храните настройки:

::: code-group
```yaml [Compose]
# В блоке environment сервиса shprotify
SHPROTIFY_LIBRARY__DIRECTORIES: '["/music", "/archive"]'
```
```toml [TOML]
[library]
directories = ["/music", "/archive"]
```
:::

Если секция `[library]` уже есть, измените строку `directories` в ней.
Каждая папка должна быть отдельной: если одна уже находится внутри другой,
сервер прочитает её вместе с родительской папкой.

Примените изменения командой `docker compose up -d` и запустите сканирование
ещё раз. О путях внутри контейнера подробнее в [настройках](./configuration.md).

## Обновите библиотеку

После добавления файлов или правки тегов запустите то же сканирование
ещё раз. Оно пропустит файлы, которые не изменились. Если нужно перечитать
все файлы, выставьте параметр `force` в `true` при запуске сканирования.
Для знакомых файлов сервер обновляет сведения о файле и сохраняет
уже принятые метаданные каталога.

Если файл убрали с диска, запись о треке останется в каталоге. Чтобы снова
его слушать, можно вернуть файл по прежнему пути.

Если музыка пополняется регулярно, можно настроить
[сканирование по расписанию](./automation.md).

## Где хранятся загрузки и обложки

Для своих файлов используйте папки библиотеки. Если включена
[загрузка с YouTube](./downloads.md), Shprotify сохраняет полученные треки
в `./data/downloads/` и добавляет их в каталог после загрузки. Эту папку
оставьте в настройках загрузок, чтобы уже добавленные треки оставались
доступны после отключения новых загрузок.

Сохранённые обложки хранятся в `shprotify.db`. Извлечение картинки из
аудиофайла запускается отдельно от сканирования. Подробнее в руководстве
[Теги и обложки](./metadata.md).
