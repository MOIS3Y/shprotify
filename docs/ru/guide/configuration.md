# Настройки и файлы

После [быстрого старта](./quick-start.md) настройки Shprotify находятся
в `compose.yaml`. Их можно менять там же. Если удобнее держать
настройки в отдельном файле, воспользуйтесь [вариантом с TOML](#настройки-в-toml).

## Где лежат файлы

Так выглядит папка установки на хосте. `.env` и `config/` появляются,
если вы добавили их сами. Файлы в `data/` создаются по мере работы.

```text
shprotify/
├─ compose.yaml
├─ .env                    # необязательно: тег образа
├─ config/
│  └─ shprotify.toml       # необязательно: настройки сервера
├─ music/                  # ваши аудиофайлы
└─ data/
   ├─ shprotify.db         # каталог, обложки и данные пользователей
   ├─ shprotify.db-wal     # служебные файлы SQLite
   ├─ shprotify.db-shm
   ├─ downloads/
   │  ├─ objects/          # добавленные в библиотеку загрузки
   │  └─ .staging/         # загрузки в работе
   └─ cache/               # кэш внешних инструментов
```

Compose связывает папки хоста с путями внутри контейнера:

| На хосте | В контейнере | Доступ |
| --- | --- | --- |
| `./data/` | `/data/` | Чтение и запись для UID/GID 1000 |
| `./music/` | `/music/` | Только чтение |
| `./config/shprotify.toml` | `/config/shprotify.toml` | Только чтение, если подключён TOML |

> [!TIP]
> Если подключите `/srv/music:/music:ro`, в настройках Shprotify укажите
> `/music`. Это путь, по которому сервер видит файлы внутри контейнера.

Рабочая папка контейнера по умолчанию находится в `/data`. От неё отсчитываются
относительные пути в настройках. Чтобы было видно, куда указывает
настройка, используйте абсолютные пути внутри контейнера.

## Изменить настройку в Compose

Например, чтобы новые сеансы входа действовали семь дней, добавьте
в существующий блок `environment` сервиса `shprotify` такую строку:

```yaml
SHPROTIFY_AUTH__SESSION_TTL_SECONDS: "604800"
```

Начните имя с `SHPROTIFY_`. Два подчёркивания `__` отделяют секцию
`auth` от ключа `session_ttl_seconds`. В YAML указывайте значения в кавычках.
Список тоже передаётся одной строкой:

```yaml
SHPROTIFY_LIBRARY__DIRECTORIES: '["/music", "/archive"]'
```

Для каждой папки укажите, откуда Docker должен её подключить.
Пример с двумя папками есть в [руководстве по библиотеке](./library.md#подключение-еще-однои-папки).

Сохраните `compose.yaml` и примените изменения:

```sh
docker compose up -d
```

Файл `.env` рядом с `compose.yaml` можно использовать для выбора образа
через `SHPROTIFY_IMAGE`. Настройки приложения из примеров передаются
контейнеру через `environment`. [Как выбрать тег образа](./deployment.md)

## Какая настройка применяется

1. Переменная окружения, если она задана.
2. Значение в TOML, если файл передан через `--config`.
3. Встроенное значение по умолчанию.

Shprotify читает TOML только по пути из `--config`. Если файл
по этому пути отсутствует или не читается, сервер сообщит об ошибке
при запуске.

> [!NOTE]
> Образ задаёт переменные для адреса сервера, пути к базе, папки загрузок
> и формата журналов. Чтобы изменить одну из них, задайте новое значение
> в `environment` файла `compose.yaml`.
>
> - `SHPROTIFY_HTTP__BIND`
> - `SHPROTIFY_DATABASE__PATH`
> - `SHPROTIFY_DOWNLOADS__DIRECTORY`
> - `SHPROTIFY_LOGGING__FORMAT`
