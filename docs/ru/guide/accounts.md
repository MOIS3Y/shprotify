# Пользователи и доступ

Библиотека общая для всех пользователей сервера. У каждого своё
избранное, плейлисты, очередь и история. Если администратор уже создан
по [быстрому старту](./quick-start.md), можно пригласить остальных.

## Добавьте пользователя

Откройте терминал в папке с `compose.yaml`. Замените `bob` именем
нового пользователя и выполните обе команды:

```sh
docker compose exec shprotify shprotify user create --name bob
docker compose exec shprotify shprotify user password --name bob
```

Первая команда создаст обычного участника. Вторая попросит дважды
ввести пароль. Символы в терминале при вводе скрыты.

Для входа в клиенте пользователю понадобятся адрес сервера, имя и пароль.
Аккаунты создаёт администратор. Самостоятельной регистрации нет.

> [!NOTE]
> Команда создания аккаунта выводит персональный API-ключ один раз.
> Для входа по паролю ключ не нужен. Храните его как пароль.

## Выберите роль

| Роль | Что можно делать |
| --- | --- |
| Участник (`member`) | Слушать музыку, собирать плейлисты и пользоваться рекомендациями. |
| Администратор (`admin`) | Всё, что может участник, а также управление аккаунтами, сканирование папок и правка данных каталога. |

Чтобы дать пользователю права администратора:

```sh
docker compose exec shprotify shprotify user role --name bob --role admin
```

Чтобы вернуть роль участника:

```sh
docker compose exec shprotify shprotify user role --name bob --role member
```

Роль меняется сразу. Пользователь может продолжить работу в той же сессии.

## Как долго действует вход

После входа по паролю сессия по умолчанию действует 30 дней.
Когда срок закончится, нужно будет войти снова. Чтобы новые сессии
действовали семь дней, задайте один из этих вариантов:

::: code-group
```yaml [Compose]
# В блоке environment сервиса shprotify
SHPROTIFY_AUTH__SESSION_TTL_SECONDS: "604800"
```
```toml [TOML]
[auth]
session_ttl_seconds = 604800
```
:::

Время указывается в секундах. У уже открытых сессий срок останется
прежним. Активность в клиенте его не продлевает.
[Как применить настройки](./configuration.md)

## Восстановите доступ

Если пользователь забыл пароль, задайте новый той же командой
`user password`. Она также подойдёт, если вы забыли пароль
администратора и у вас остался доступ к терминалу на сервере. Подставьте
имя нужного пользователя:

```sh
docker compose exec shprotify shprotify user password --name bob
```

Все активные сеансы входа по паролю завершатся. Персональные API-ключи
останутся действующими.

Если потеряли или случайно раскрыли API-ключ, отзовите ключи аккаунта:

```sh
docker compose exec shprotify shprotify user revoke --name bob
```

Команда отзывает все персональные ключи пользователя. Вход по паролю
и личные данные сохраняются. Если нужен новый ключ, выпустите его
командой `user token --name bob`. [Как работает авторизация в API](../clients/authentication.md)

## Кто видит библиотеку

В Compose из быстрого старта каталог закрыт для гостей. Чтобы посмотреть
список музыки, искать треки и открывать обложки, нужно войти.

Если хотите разрешить просмотр каталога без входа, задайте
`SHPROTIFY_LIBRARY__PUBLIC_CATALOG: "true"` в Compose или
`public_catalog = true` в секции `[library]` файла TOML. При запуске
со встроенными настройками каталог открыт для просмотра. Для закрытого
сервера явно задайте `false`.

- Для прослушивания нужна авторизация или временная ссылка на аудио,
  которую получает плеер.
- Опубликованный плейлист видят вошедшие пользователи. Редактирует
  его владелец.
- Избранное, история и личные задания привязаны к аккаунту. У оператора
  сервера есть доступ к базе, где эти данные хранятся.

Если веб-плеер открывается с другого домена, укажите адрес плеера
в [настройках CORS](./proxy.md#если-веб-плеер-на-другом-домене).
